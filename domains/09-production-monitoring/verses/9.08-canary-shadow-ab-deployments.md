# 9.08 — Canary, shadow & A/B deployments

**Objective:** 9.3

- **Canary**: route a small % of live traffic to the new version, watch metrics, ramp up
  if healthy, roll back if not.
- **Shadow**: send a copy of traffic to the new version without returning its responses
  — compare offline, zero user risk.
- **A/B**: split traffic to measure a business/quality metric difference statistically.

Serve multiple versions simultaneously via the model repo version policy (8.18).

**Chain →** These strategies need a clean rollback — how is that guaranteed? (9.09)
