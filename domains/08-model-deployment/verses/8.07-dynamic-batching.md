# 8.07 — Dynamic batching

**Objective:** 8.2

Triton's **dynamic batcher** holds incoming requests briefly (up to
`max_queue_delay_microseconds`) to combine them into a larger batch before running the
model — raising throughput/GPU utilization. It batches at the **request** level and waits
for the batch to **finish together**. Great for fixed-size/non-autoregressive models
(encoders). For autoregressive LLMs with variable output lengths it's suboptimal (short
requests wait for long ones) — hence continuous batching (8.08).
