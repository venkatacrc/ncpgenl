Verse 1.01 — Transformer block anatomy
Objective 1.2

A transformer block is a residual stream of width d_model with two sublayers,
each wrapped as x = x + Sublayer(Norm(x)) (pre-LN, the modern default). The
original paper used post-LN Norm(x + Sublayer(x)), which needs LR warmup to stay
stable. Sublayer 1 = multi-head self-attention; sublayer 2 = position-wise FFN (two
linear layers + nonlinearity, inner dim ≈ 4·d_model, GELU/SwiGLU). The residual
stream is the "highway" every sublayer reads from and writes to; its width d_model
is the model's information bandwidth.

# pre-LN block (schematic)
def block(x, attn, ffn, ln1, ln2):
    x = x + attn(ln1(x))     # sublayer 1: mixes tokens
    x = x + ffn(ln2(x))      # sublayer 2: per-token transform
    return x
Chain → Everything hinges on what the attention sublayer computes — so what is inside it? (1.02)
Verse 1.02 — Scaled dot-product attention
Objective 1.2

Attention mixes tokens by content similarity:

$$\text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

with Q=XW_Q, K=XW_K, V=XW_V. The 1/√d_k scale exists because for
unit-variance q,k the dot product q·k has variance d_k; without scaling,
logits grow with d_k, softmax saturates toward one-hot, and gradients through it
vanish. Dividing by √d_k restores unit-variance logits.

import torch, math
def attention(Q, K, V, mask=None):           # Q,K,V: [B, h, T, d_k]
    scores = Q @ K.transpose(-2, -1) / math.sqrt(Q.size(-1))
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    return torch.softmax(scores, dim=-1) @ V
Chain → One head attends in only one subspace — how do we attend in several at once? (1.03)
Verse 1.03 — Multi-head attention
Objective 1.2

Split into h heads of width d_k = d_model/h, attend independently, concatenate,
project with W_O:

$$\text{MHA}(X)=\text{Concat}(\text{head}_1,\dots,\text{head}_h)W_O,\quad \text{head}_i=\text{Attention}(XW_Q^i,XW_K^i,XW_V^i)$$

Total parameter/FLOP cost ≈ one full-width head, but heads specialize (syntax,
coreference, positional patterns). GQA/MQA later share K,V across heads to shrink the
KV cache (see 4.26).

def split_heads(x, h):        # [B, T, d_model] -> [B, h, T, d_k]
    B, T, d = x.shape
    return x.view(B, T, h, d // h).transpose(1, 2)
# merge is the inverse, then @ W_O
Chain → Attention is permutation-invariant — reorder tokens, output set is unchanged. How does the model know order? (1.04)
Verse 1.04 — Positional encoding
Objective 1.2

Order is injected explicitly.

  • Sinusoidal (fixed, additive): PE(pos,2i)=sin(pos/10000^{2i/d}),
    PE(pos,2i+1)=cos(...). Extrapolates modestly.
  • Learned absolute: trainable position table; cannot extrapolate past trained
    length.
  • RoPE (rotary): rotates Q,K by a position-dependent angle so the dot product
    depends only on the relative offset; strong extrapolation; default in modern
    decoders (Llama, Qwen).
  • ALiBi: adds a linear distance penalty to attention logits; cheapest, strong
    extrapolation.
import torch
def sinusoidal(T, d):
    pos = torch.arange(T)[:, None]
    i   = torch.arange(0, d, 2)[None, :]
    ang = pos / (10000 ** (i / d))
    pe = torch.zeros(T, d); pe[:, 0::2] = ang.sin(); pe[:, 1::2] = ang.cos()
    return pe
Chain → These blocks stack identically, but encoder and decoder differ in the attention mask. What is an encoder? (1.05)
Verse 1.05 — Encoder stack (bidirectional)
Objective 1.1

An encoder applies unmasked self-attention: every position attends to all
positions, left and right. Output is a contextual representation of the whole
input — ideal for understanding tasks: classification, NER, retrieval embeddings
(BERT, RoBERTa). It cannot generate autoregressively because it "sees the
future." Trained with masked language modeling (see 4.28).

# no causal mask: full [T, T] attention allowed
attn_mask = None            # only padding mask applied, never a causal triangle
Chain → So what do we use when we must generate text token by token? (1.06)
Verse 1.06 — Decoder stack (causal)
Objective 1.1

A decoder applies a causal mask: position t attends only to ≤ t. Implemented
by adding -∞ to the upper triangle of QKᵀ/√d_k before softmax, forcing those
weights to 0. This enforces autoregression p(x_t | x_{<t}), enabling generation
(GPT family). At inference, past keys/values are cached (KV cache, see 4.26) so
each new token costs O(seq) not O(seq²).

import torch
def causal_mask(T):
    return torch.tril(torch.ones(T, T)).bool()   # lower-triangular True = allowed
Chain → What about tasks that must both fully understand an input and generate a different output? (1.07)
Verse 1.07 — Encoder-decoder (cross-attention)
Objective 1.1

Seq2seq models (T5, BART, original Transformer) pair a bidirectional encoder with
a causal decoder joined by cross-attention: the decoder supplies Q, the
encoder's final states supply K,V. Decoding is thus conditioned on a
fully-contextualized source — the natural fit for translation and summarization where
source/target lengths and vocabularies differ. Cost: you pay for both stacks plus
cross-attention.

# decoder layer has THREE attention calls:
h = h + self_attn(ln1(h), mask=causal)          # 1: causal self-attn
h = h + cross_attn(ln2(h), kv=encoder_states)   # 2: Q=decoder, K,V=encoder
h = h + ffn(ln3(h))                             # 3: FFN
Chain → All three architectures emit hidden states we call embeddings — but what is an embedding, precisely? (1.08)
Verse 1.08 — The concept of embeddings

Objectives: 1.6, (1.8 support)

An embedding maps a discrete token id to a dense vector via lookup in the embedding
matrix E ∈ ℝ^{V×d} (V = vocab size). Training arranges these vectors so geometric
proximity ≈ semantic/functional similarity. Weight tying reuses E (transposed)
as the output projection to logits, cutting parameters and coupling input/output
representations. "Embedding" also names any later hidden state used as a
sentence/document vector.

import torch.nn as nn
emb = nn.Embedding(V, d)          # lookup table E: [V, d]
lm_head = nn.Linear(d, V, bias=False)
lm_head.weight = emb.weight        # weight tying (input emb == output projection)
Chain → How do we actually pull a usable sentence embedding out of an encoder? (1.09)
Verse 1.09 — Extract embeddings from an encoder

Objectives: 1.3, 1.6

Two standard poolings over the encoder's last hidden state: the [CLS] token vector,
or masked mean pooling over token vectors. Mean pooling usually wins unless the
model was fine-tuned to make [CLS] a sentence representation (Sentence-Transformers
exist precisely for this reason).

from transformers import AutoTokenizer, AutoModel
import torch
tok = AutoTokenizer.from_pretrained("bert-base-uncased")
enc = AutoModel.from_pretrained("bert-base-uncased").eval().cuda()
b = tok(["a cat sat", "a dog ran"], padding=True, return_tensors="pt").to("cuda")
with torch.no_grad():
    h = enc(**b).last_hidden_state              # [B, T, d]
m = b.attention_mask.unsqueeze(-1)              # [B, T, 1]
mean_emb = (h * m).sum(1) / m.sum(1)            # masked mean pooling -> [B, d]
Chain → Decoders have no `[CLS]` and attend only leftward — how do we get an embedding from one? (1.10)
Verse 1.10 — Extract embeddings from a decoder
Objective 1.3

Use the last non-pad token's final hidden state — under causal masking it is the
only position that has attended to the entire sequence. This requires left padding
so the true last token sits at index -1; right padding returns a pad vector and
collapses your embeddings.

from transformers import AutoTokenizer, AutoModel
import torch
tok = AutoTokenizer.from_pretrained("gpt2"); tok.padding_side = "left"
tok.pad_token = tok.eos_token
dec = AutoModel.from_pretrained("gpt2").eval().cuda()
b = tok(["a cat sat", "a dog ran too"], padding=True, return_tensors="pt").to("cuda")
with torch.no_grad():
    h = dec(**b).last_hidden_state              # [B, T, d]
last_emb = h[:, -1, :]                          # left-padded => real last token
Chain → Now the decoder can produce hidden states and logits — how do we turn logits into the next token? (1.11)
Verse 1.11 — Sampling I: greedy, beam, temperature

Objectives: 1.4, 1.5

From logits z, p = softmax(z).
- Greedy = argmax; deterministic, myopic, repetitive.
- Beam search keeps the b highest-probability sequences (summed, usually
length-normalized log-probs); maximizes likelihood — good for constrained tasks
(translation), bad for open-ended text (bland, degenerate loops).
- Temperature rescales before softmax: p_i = softmax(z_i/T). T<1 sharpens
(greedier), T>1 flattens (more random), T→0 ≡ greedy (implementations
special-case it; literal z/0 is undefined).

import torch
def sample_temp(logits, T=0.7):
    p = torch.softmax(logits / max(T, 1e-6), dim=-1)
    return torch.multinomial(p, 1)
Chain → Temperature reshapes the *whole* distribution — how do we instead cut off the unreliable tail? (1.12)
Verse 1.12 — Sampling II: top-k, top-p (nucleus), repetition penalty

Objectives: 1.4, 1.5

  • Top-k: keep the k highest-prob tokens, renormalize, sample — fixed count
    regardless of confidence.
  • Top-p / nucleus: keep the smallest set whose cumulative probability ≥ p, then
    sample — an adaptive count that stays small when confident and widens when
    uncertain.
  • Repetition penalty: divide logits of already-generated tokens by r>1 to
    suppress loops.

Common recipe: temperature≈0.7, top_p≈0.9.

import torch
def top_p(logits, p=0.9):
    s, idx = torch.sort(logits, descending=True)
    cum = torch.softmax(s, -1).cumsum(-1)
    s[cum > p] = float("-inf")            # drop the tail beyond nucleus
    return idx[torch.multinomial(torch.softmax(s, -1), 1)]
