# 3.17 — Training a tokenizer & vocab-size trade-offs

**Objective:** 3.3

Train on a representative sample; choose vocab size. **Larger vocab** → shorter
sequences (fewer tokens/word, lower fertility), faster inference, but a bigger embedding
+ softmax matrix (more params/memory) and rarer tokens undertrained. **Smaller vocab**
→ longer sequences, more compute per document. Typical LLM vocabs: 32k–256k. Match the
tokenizer to the target languages/domains (code, multilingual need larger vocab).

```python
from tokenizers import ByteLevelBPETokenizer
tk = ByteLevelBPETokenizer()
tk.train(files=["corpus.txt"], vocab_size=32000, min_frequency=2)
```
